# แผนงาน: AI วิเคราะห์ผลการวิ่งแบบรายวัน (Daily Analysis with Historical Context)

**วันที่:** 2026-02-24
**สถานะ:** เสร็จสิ้น (Done)

## เป้าหมาย (Objective)
ให้ AI (Gemini) ทำการวิเคราะห์ผลการวิ่งแบบอัตโนมัติทุกครั้งที่มีการ Import ไฟล์ `.fit` เข้าสู่ระบบ โดยผลการวิเคราะห์นี้จะต้อง**อ้างอิงจากข้อมูลสถิติการวิ่งทั้งหมดในอดีตเสมอ** (Historical Context) เพื่อให้ผู้ใช้ได้รับคำแนะนำและเห็นพัฒนาการของตนเองอย่างมีบริบท ไม่ใช่แค่วิเคราะห์แยกเป็นครั้งๆ

## ขอบเขตการทำงาน (Scope of Work)

1. **การดึงข้อมูล (Data Retrieval):**
   - เมื่อผู้ใช้ทำการ Import ไฟล์วิ่งเสร็จสมบูรณ์ในหน้า `Sessions.tsx` ระบบจะทำการดึงข้อมูล Session ล่าสุดที่เพิ่งรันเข้ามา
   - ดึงข้อมูล Sessions ทั้งหมดในอดีต (หรือข้อมูลสรุปภาพรวม/แนวโน้ม) จากฐานข้อมูล `sessionRepository`
   - ดึงข้อมูล Profile ผู้ใช้ (เช่น อายุ, น้ำหนัก, Max HR, เป้าหมาย) เพื่อประกอบการวิเคราะห์

2. **การบูรณาการ AI (AI Integration):**
   - สร้างฟังก์ชัน API หรือ Service ดึงข้อมูลทั้งหมดที่กล่าวมา ส่งเป็น Prompt ให้กับ Gemini AI รุ่นที่เหมาะสม (เช่น `gemini-1.5-pro` หรือ `gemini-1.5-flash` หากต้องการความรวดเร็ว)
   - Prompt ต้องถูกออกแบบให้ AI ควบคุมโครงสร้างการตอบกลับ (เช่น ถอดความเข้า JSON หรือ Markdown ที่อ่านง่าย) โดยเน้นย้ำคำสั่ง "ให้พิจารณาเปรียบเทียบกับภาพรวมการวิ่งทั้งหมดของยูสเซอร์เสมอ"

3. **การแสดงผล (User Interface):**
   - ในหน้า Session Detail ของการวิ่งนั้นๆ หรือในส่วนแจ้งเตือน (Notification/Modal) หลัง Import ให้แสดง "AI Insights" หรือ "บทวิเคราะห์จากโค้ช AI"
   - ข้อมูลการวิเคราะห์ควรประกอบด้วย:
     - **สรุปพัฒนาการ:** การวิ่งครั้งนี้ดีขึ้นหรือแย่ลงเมื่อเทียบกับค่าเฉลี่ยที่ผ่านมา (เช่น Heart Rate Zone ต่ำลงในเพซที่เท่าเดิม)
     - **คำแนะนำ:** สิ่งที่ควรปรับปรุงในเซสชันหน้า (เช่น "ควรพักผ่อนให้มากขึ้น เนื่องจาก HR สูงกว่าปกติในเพซนี้")

4. **สถาปัตยกรรม (Architecture):**
   - เพิ่มคอลัมน์ `ai_analysis` ในตาราง `sessions` เพื่อเก็บผลวิเคราะห์ ไม่ต้องเรียก API ซ้ำทุกครั้งที่เปิดดู
   - สร้างโมดูลใหม่ `aiAnalysisService.ts` จัดการเรื่อง Prompt และการคุยกับ AI Agent โดยเฉพาะ

## สิ่งที่ต้องพิจารณา (Considerations)
- **Token Limits:** หากส่ง Session History จำนวนมาก (เช่น เป็นร้อยหรือพันครั้ง) อาจจะเกิน Context Window ควรกำหนดให้ส่งเฉพาะข้อมูลสรุปสถิติ (Aggregated Data) หรือข้อมูล X เซสชันล่าสุด เพื่อให้ AI นำไปประมวลผล
- **API Keys:** จำเป็นต้องมีกลไกจัดการ Gemini API Key ที่ปลอดภัย (อาจจะเป็น Setting menu ให้ผู้ใช้ใส่ Key เอง หรือจัดการผ่าน Environment Variable)
